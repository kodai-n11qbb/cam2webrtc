# 設定とデプロイ仕様書 (Configuration & Deployment)

本ドキュメントは、Cam2WebRTCアプリケーションの動作設定（`config.json`）、ポートの割り当て、TLS証明書の自動生成処理、およびモバイルデバイスからの動作検証手順について解説します。

---

## 1. 設定ファイル仕様 (`config.json`)

アプリケーションの起動設定は、プロジェクト直下の `config.json` にて管理されます。

### 1.1 プロパティ詳細

| 設定キー | データ型 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- |
| `signaling_addr` | String | `"0.0.0.0:8080"` | HTTPサーバーおよびWebSocketシグナリングが使用するバインドIPとポート。 |
| `stun_addr` | String | `"0.0.0.0:3478"` | 内蔵STUNサーバーが使用するUDPバインドIPとポート。 |
| `turn_addr` | String | `"0.0.0.0:3479"` | 内蔵TURNサーバーが使用するUDPバインドIPとポート。 |
| `ice_servers` | Array | `[{"urls":["stun:localhost:3478"]}]` | WebRTC接続時にクライアントに提供されるICEサーバーのリスト。 |
| `video_constraints`| Object | *後述* | カメラ起動時の要求ビデオスペック（解像度など）。 |
| `tls_enabled` | Boolean | `false` | HTTPSおよびWSS接続（TLS暗号化）を有効にするか。 |
| `tls_cert_path` | String | `"cert.pem"` | TLSサーバー証明書の保存/読み込みパス。 |
| `tls_key_path` | String | `"key.pem"` | TLS秘密鍵の保存/読み込みパス。 |
| `admin_api_enabled` | Boolean | `false` | 管理用HTTP REST API（Uptime取得、ルーム強制終了等）を有効にするか。 |
| `admin_api_key` | String | `"admin-secret-key"`| 管理用HTTP REST APIへのアクセスに要求する認証用APIキートークン。 |
| `default_room_id` | String | `"default-room"`| ルーム作成APIがデフォルトで使用するルームID。接続URLの既定値。 |

### 1.2 `video_constraints` の構造例
MediaStream APIの制約パラメータを指定します。
```json
"video_constraints": {
    "width": {
        "ideal": 1280
    },
    "height": {
        "ideal": 720
    }
}
```
※ 配信開始時、フロントエンドの `navigator.mediaDevices.getUserMedia` にそのまま渡され、理想的な配信解像度が指示されます。

## 2. ポート割り当てとネットワーク要件

同一ネットワーク内での通信を許可するために、ファイアウォールで以下のポートを開放する必要があります。

| ポート番号 | プロトコル | 用途 | サービス名 |
| :--- | :--- | :--- | :--- |
| **8080** | **TCP** | HTTPS / WSS / HTTP | Webサーバー・シグナリング |
| **3478** | **UDP** | STUNパケット受信 | STUNサービス |
| **3479** | **UDP** | TURNパケット受信 | TURNサービス |
| **49152 - 65535** | **UDP** | TURNリレー通信 | 動的割り当てポート範囲（TURN用） |

## 3. 自己署名証明書 (TLS) の自動生成と Secure Context

### 3.1 WebRTCにおけるTLSの必須要件
現代のブラウザセキュリティモデルでは、カメラやマイクなどのハードウェアへのアクセス（`getUserMedia`）は **Secure Context（安全なコンテキスト）** 内でのみ許可されます。
Secure Contextとして認められるのは以下のいずれかのみです。
1. `localhost` または `127.0.0.1` 経由のアクセス
2. **`https://` (TLS暗号化)** 経由のアクセス

したがって、同じLAN内の別のPCやスマートフォンなどのモバイルデバイスから接続して配信を行う場合、HTTP（`http://192.168.X.X:8080`）ではカメラが起動せず、動作させることができません。このため、モバイルデバイス等からカメラ（Sender）にアクセスして配信を行う場合は、`config.json` にて `tls_enabled: true` に設定する必要があります（本システムではデフォルトで `tls_enabled: false` となっています）。

### 3.2 サーバー側での自己署名証明書自動生成
本システムでは、起動時に `tls_cert_path` および `tls_key_path` で指定された場所に証明書が存在しない場合、Rustのライブラリ `rcgen` を用いて自己署名証明書を自動生成します。

- **ホスト名の解決 (SAN)**:
  自動生成の際、サーバーは自身のすべてのローカルIPアドレス（ローカルホスト、および `192.168.X.X` などの実IP）を自動検出し、証明書の「サブジェクト代替名（Subject Alternative Name: SAN）」に登録します。これにより、モバイルデバイスからIPアドレス直打ちでアクセスした際のTLS検証エラーを最小限に抑えています。

## 4. モバイルデバイスからのアクセス手順とトラブルシューティング

自己署名証明書を使用しているため、モバイルブラウザで初回アクセスする際にはセキュリティ警告が表示されます。以下の手順で警告をバイパスしてください。

### 4.1 iOS (Safari) の手順
1. `https://[サーバーのローカルIP]:8080/sender.html` にアクセスします。
2. 「この接続はプライベートではありません」という警告画面が表示されます。
3. 画面下部の **「詳細を表示」** をタップします。
4. 説明文の最後にある **「このWebサイトを閲覧」** のリンクをタップします。
5. ポップアップが表示されるので **「Webサイトを閲覧」** をタップして進みます。

### 4.2 Android (Chrome) の手順
1. `https://[サーバーのローカルIP]:8080/sender.html` にアクセスします。
2. 「接続がプライベートではありません」という警告画面が表示されます。
3. 画面下部の **「詳細設定」** ボタンをタップします。
4. **「[サーバーのローカルIP] にアクセスする（安全ではありません）」** をタップして進みます。

### 4.3 トラブルシューティング
- **カメラが起動しない場合**:
  - URLが `http://` ではなく `https://` で始まっているか確認してください。
  - ブラウザからのカメラ・マイクの使用許可ポップアップで「許可」を選択しているか確認してください。
- **WebSocket接続が失敗する場合**:
  - サーバーを起動しているPCのファイアウォール（Windows DefenderやmacOSのファイアウォール）がTCPポート8080のインバウンド接続をブロックしていないか確認してください。
- **P2P接続（映像の受信）が開始されない場合**:
  - LAN内でUDPポート（3478, 3479）およびWebRTCの動的ポートがブロックされていないか確認してください。
